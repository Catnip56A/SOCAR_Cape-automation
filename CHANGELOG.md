# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and version numbers come from the [VERSION](VERSION) file.

## [1.0.16] - 2026-09-29
### Fixed
- CTR Tracker: a USD CTR's Value cell showed as a date (e.g. 4634 → `07-Sep-12`) with an off fill colour. The writer stamped a hard-coded style id (`159`, set for an older tracker) on every USD value, but style ids are positions in each workbook's own style table and 159 is a date format in the real tracker. The Value cell now gets the style that matches its current look (fill, border, alignment) with the currency's number format — `"$"#,##0.00` for USD, `#,##0.00 [$₼-42C]` for AZN — looked up in the tracker's own `styles.xml` at write time; if no such style exists, the cell keeps its own style instead of guessing an id. `value_style_by_currency` in `template_config.json` / `config.py` is replaced by `value_format_by_currency`; `_style_with_number_format` (`ctr_tools/tracker_fast.py`). USD rows written by earlier versions may still carry the wrong format and need fixing by hand.

### Changed
- CTR Tracker: the "Overwrite rows that already have data" checkbox and its "Overwrite this row" / "Add as separate revision" options are gone — every write now behaves as "Add as separate revision" (same CTR + currency + revision is updated in place; a different revision gets its own row in ascending revision order). `write_entries_fast` defaults changed accordingly (`ctr_tools/tracker_fast.py`, `ctr_tools/tracker_window.py`).
- CTR Tracker: a blank spare row is now only used if it keeps the CTR's rows in ascending revision order. Previously, with several spare rows reserved for one CTR, a lower/blank revision loaded after a higher one landed in the next spare *below* it (e.g. revision 1 above the no-revision row). Now that spare is left alone and a row is inserted at the ordered position via Excel (skipped with a message if Excel isn't available), and the results dialog lists each spare row left blank. Re-loading a revision that already exists in the tracker now updates that row instead of filling another spare. `_check_spare_row`, `_filled_revision_rows` (`ctr_tools/tracker_fast.py`); `write_entries_fast` now returns a fourth value, `notes`.

### Known issues
- CTR Tracker: formulas the writer adds (USD equivalent, labor, totals) are saved without a calculated result and Excel does not always recalculate them on open, so those cells can look empty until refreshed. Workaround: press Ctrl+Alt+Shift+F9 in Excel to recalculate the whole workbook (documented in the User Guide). Proposed permanent fix, not yet made: set `fullCalcOnLoad="1"` on the workbook's `calcPr` when writing (`write_entries_fast`, `ctr_tools/tracker_fast.py`).

## [1.0.13] - 2026-09-10
### Added
- CTR Tracker: writing a Description now makes sure that cell is covered by the tracker's own "flag repeated Descriptions" red-highlight rule (a `duplicateValues` conditional format on column P) — covers a normal write, an overwrite, and a newly inserted "separate revision" row alike, since all three write their Description through the same code path. The real rule has been fragmented by years of manual row insertions into 100+ separate range pieces, with a handful of gaps where no fragment covers a row at all (confirmed: 22 such rows in the real file) — this heals a gap the moment our code happens to write into that row, rather than leaving it silently unflagged. A `duplicateValues` rule only ever compares cells *within its own range* (confirmed against the OOXML spec) — so the fix adds the row as one more token onto whichever existing rule on the column already covers the most cells, rather than creating an isolated single-cell rule, which would have "covered" the cell in name only and could never actually flag anything as a duplicate. `_ensure_duplicate_check_coverage` (`ctr_tools/tracker_fast.py`).
- CTR Tracker: a new required "Job Type" dropdown (column K, "Job type (Core Crew, Projects, FM, TAR)" in the real tracker's header) — choices are `CORE CREW`, `PROJECTS`, `FM`, `FM PROCESS`, `FM DRILLING`, `Drilling`, `TAR`, `TAR & SHUTDOWN`, matching the casing actually used across the tracker's ~7,300 existing rows (`ctr_tracker_job_types` in `template_config.json`). "Add to Batch" now refuses an entry with no Job Type selected, the same way it already refuses one with no Location. Shown as its own column in the batch table and written into column K like Location/Client/Project Code — protected from being clobbered on an already-filled row unless "Overwrite" is on. `job_type_options`, `CTREntry.job_type` (`ctr_tools/tracker.py`); `_job_type_combo` (`ctr_tools/tracker_window.py`); `col_job_type` (`ctr_tools/tracker_fast.py`).
- MR vs CTR Comparator: Combined View now has "MR Document"/"CTR Document" columns — each lists every file that contributed to that Stock Code's totals (comma-joined when it spans more than one), hidden by default and toggled by the same "Show Document Names" button as the other tabs (no changes needed there — it already dynamically follows whichever table is showing). A comparison saved before this existed still loads and shows blank in those two columns rather than failing, since there's no historical per-row document data to backfill. `_aggregate_combined`, `_refresh_combined_tables` (`app.py`).
- MR vs CTR Comparator: each table listed under Step 2 — MR/CTR Tables now has its own remove button (✕) to delete it entirely — distinct from unchecking it, which only excludes it from Compare without removing it (its tooltip now says so explicitly). If every table from a given Step 1 file gets removed this way, that file's entry turns red with an explanatory tooltip instead of silently still looking "loaded" with nothing left to contribute; it heals back to normal the moment the file has a table again. `_remove_table`, `_refresh_file_warnings` (`app.py`).

### Fixed
- CTR Tracker: a batch inserting both a currency's brand-new first row for a CTR *and* a new revision of that CTR's other, already-existing currency could compute the exact same target row for both — and since ties were broken by batch submission order, the new-currency row could win the slot that actually belonged to the revision insert, pushing it to the bottom of the whole CTR block instead of landing next to its own currency's row (e.g. a CTR's first USD line, submitted just before a second AZN revision, would shove that AZN revision below the new USD row instead of next to AZN's first). Ties are now broken by which insertion actually has a required position: a revision insert (which must land in a specific place relative to its own currency's existing rows) always wins the tie over a currency's brand-new first row (which has no such constraint — it only needs to be somewhere in the CTR's block), regardless of which was submitted first. `_plan_insertions` (`ctr_tools/tracker_fast.py`).
- CTR Tracker: writing two revisions of the same CTR number + currency in one batch (e.g. a corrected line and its original, or a currency's first two revisions together) silently misordered them — the second revision could land *above* the first regardless of which was actually newer, because the row it needed to compare itself against wasn't "real" yet as far as that single write pass could see, and it fell back to a currency-mismatch path that just appends after the last row instead of placing it correctly. Two entries in the same batch for the same CTR number + currency are now detected up front and the later one is skipped with a clear, matchable reason (`IN_BATCH_CONFLICT_MARKER`) instead of being silently misordered — it stays in the batch table (nothing else in the batch is affected) and is automatically retried in a follow-up batch after a 3-second countdown (cancellable), by which point the first revision is genuinely on disk and orders correctly against it. A batch with more than two revisions of the same CTR+currency resolves over several such rounds. `_plan_insertions` (`ctr_tools/tracker_fast.py`); `_maybe_start_retry_countdown`/`_on_retry_tick`/`_cancel_retry_countdown`, `_start_write` (split out of `_write_batch`, `ctr_tools/tracker_window.py`).
- CTR Tracker: `_remove_written_from_batch` matched entries back to batch rows by CTR number alone, which is ambiguous whenever two rows in a batch share one (exactly the scenario above) — it could drop the entry that still needed writing and leave the already-written one sitting in the batch table instead, causing it to be resubmitted and, if "Overwrite" was off, silently re-skipped forever. `write_entries_fast`'s `written`/`skipped` results now carry each entry's own position in the submitted list, and removal matches on that instead of on CTR number text.
- MR vs CTR Comparator: the MR/CTR preview tables (below Step 2) could keep showing a previous table's rows after unchecking or removing the last remaining table for a side, or after clicking "Clear" — none of those cleared the preview, only adding/selecting more data ever refreshed it. `_refresh_inline_previews` now always reflects the current state instead of only refreshing when there's data to show, and `_clear` now calls it at all (previously it never did). `app.py`.
- Popups — tooltips, and defensively other floating widgets like combo-box dropdowns, menus, and dialogs — could render with a solid black background instead of their intended styling, in a way that didn't depend on timing and was confined to one specific area of the app. Root-caused to a per-widget `setStyleSheet("background: transparent;")` on the comparator's scrollable controls container (`ctrl`, wrapping Step 1/Step 2's file lists, table lists, and previews): applying *any* stylesheet to a widget switches Qt to its CSS engine for that widget's entire descendant subtree, which broke `QToolTip` rendering for everything inside it while tooltips outside it (Compare/Load Comparison buttons, siblings of that container) were unaffected — exactly the boundary that let this be traced. Replaced with `ctrl.setAutoFillBackground(False)`, which achieves the same visual effect via the normal Qt default (a plain `QWidget` doesn't autofill its background anyway) without ever invoking the CSS engine for that subtree. Also added defensive explicit backgrounds for `QMenu`/`QComboBox` dropdowns/`QDialog`/`QMessageBox` and forced a light colour scheme (`app.styleHints().setColorScheme(Qt.ColorScheme.Light)` plus a full `QPalette`) as belt-and-suspenders, in case Windows dark-mode auto-detection is a contributing factor on some machines even though it wasn't the actual cause here. `app.py`'s entry point.

### Changed
- CTR Tracker: column B ("No", a running row-count formula) is no longer written on a newly inserted "separate revision" row — previously a formula referencing the row above was seeded onto the new row and the row pushed down by the insert had its own formula repaired to match. Neither happens anymore; B is left alone. `insert_revision_rows` (`ctr_tools/tracker_xlwings.py`); the now-unused `col_row_counter`/`row_counter_formula` config keys were removed.
- MR vs CTR Comparator: "Load Comparison…"'s picker now lists saved comparisons by reading a small `.meta.json` sidecar (label, timestamp, MR/CTR filenames) instead of parsing every comparison's full JSON — previously listing had to load each file's complete display/table payload just to read those four fields. A comparison saved before the sidecar existed still lists correctly (its full file is read once as a fallback), and gets a sidecar of its own the next time it's saved. `_write_meta_sidecar`, `list_saved_comparisons` (`comparison_history.py`).
- CTR Generator: saving a Match-By alias or a Description rename that's identical to what's already stored no longer rewrites the whole `match_aliases.json`/`desc_renames.json` file — only an actual change triggers the write. `set_alias` (`ctr_tools/aliases.py`), `set_desc_rename` (`ctr_tools/desc_renames.py`).
- MR vs CTR Comparator: the Rate/Rechargeable and Qty/Unit mismatch scans (run on every Compare) are now vectorized instead of iterating row by row — `_find_rate_rechargeable_mismatches` uses `.map()` over just the two needed columns instead of `.iterrows()` reconstructing a full mixed-type row each time, and the Qty/Unit scan reads each column once and zips them instead of two separate `.iloc[row_idx][col]` lookups per row (`app.py`).
- Failures that were previously swallowed silently (`except: pass`) now log a warning (or debug, for routine per-sheet format probes) instead of leaving no trail: alias/preset/description-rename load-or-seed failures (`ctr_tools/aliases.py`, `ctr_tools/desc_renames.py`, `ctr_tools/presets.py`), the CTR Tracker falling back to a workbook's first sheet when neither an AZN nor USD main sheet is found (`_main_sheet`, `ctr_tools/tracker.py`), and the MR/CTR parser's named-range/format-detection probes and a sheet that fails to parse after being detected as parseable (`sheet_parser.py`).
- `ctr_tools/config.py`'s `load_config()` now merges a list-shaped config section (e.g. the new `ctr_tracker_job_types`) by replacing it outright with the file's own list rather than assuming every section is a dict — previously any non-dict `_DEFAULTS` section would crash on load.
- MR vs CTR Comparator: the results panel's "Maximize" toggle now also hides the step indicator and the pinned Compare/Load Comparison row, not just the scrollable file-list pane — it previously left those visible, so maximizing didn't actually cover the whole tab the way the name implied. `_set_controls_chrome_visible` (`app.py`).
- `ctr_generator/` renamed to `ctr_tools/` — the folder houses the entire CTR Tracker (`tracker.py`, `tracker_fast.py`, `tracker_window.py`, `tracker_xlwings.py`, ~2,200 lines) alongside the Generator, so the old name undersold its contents. Every import, `app.spec` data-file/hidden-import entry, and reference in `CLAUDE.md`/`README.md`/`USER_GUIDE.md` was updated; moved via `git mv` so per-file history is preserved. The persisted user-data directory name (`%APPDATA%\SOCAR\CTRGenerator\`) and the `QSettings("SOCAR", "CTRGenerator")` identifiers are independent, separately-hardcoded strings and were deliberately left unchanged, so existing installs' saved presets/renames/aliases and window settings aren't affected.

### Removed
- The unused `streamlit` dev-dependency (`pyproject.toml`) and `justfile`'s `legacy` recipe, which ran a `legacy_streamlit.py` reference app that no longer exists anywhere in the repo.

## [1.0.10] - 2026-09-02
### Added
